# 0.12 功能与支持范围

本表描述当前可用模块及限制，不代表参考产品功能已经完整覆盖。完整目标与缺口以 [官网逐项核对](product/PARITY-MATRIX.md) 为准；可选自托管版已提供账号、市场、跨设备与积分；真实模型质量、微信凭据和客户端游戏行为仍有未验项目。

| 能力 | 已实现 | 边界 |
| --- | --- | --- |
| 自托管工作室 | 邀请/密码账号、独立项目/素材/设置、跨设备会话、同账户修订冲突检查、空闲回收 | 默认本地版免账号；需自己的 HTTPS 与服务器，不是已公开部署的站点 |
| 托管模型市场 | 来源/许可、不可变修订、指定版本审核、搜索/三维预览、下载/收藏/导入/更新/下架 | 无支付交易、举报申诉或自动权利鉴定 |
| 平台积分/线路 | SQLite 预留/结算/退款/中断恢复、新用户 1000、每日 10、投稿审核奖励、模型专用令牌 | 用量由服务商报告；公益线路由运营者承担费用，无附赠商业 API 或支付充值 |
| 微信登录 | 官方网站应用二维码授权、短期 state/浏览器绑定、服务端授权码交换、首次账号创建 | 需要运营者资质/凭据；协议实现，未真实扫码验收 |
| AI 代码扩展 | Java 命名空间内完整源码/JSON 修改，版本 API 摘录、上一轮代码上下文、日志修复与重新编译 | 四目标真实错误→修复通过；不能改依赖/脚本，禁止宿主接口；游戏行为和真实模型未验 |
| 素材会话 | 当前模型/UV/姿态/动画上下文，最近 12 条要求、100 个历史结果、持久化、恢复旧素材 | 100 个会话，使用现有素材库限额；复杂层级格式仍未支持 |
| 身体预览 | 背部/披风位置调整，跟随人形，素材/bbmodel 保留 | 预览位置不是已实现游戏装备行为 |
| 自动创作 | 一句需求 → 规格 → 素材生成/绑定 → 工程 → 真实构建/打包 → 完整版本；继续修改、取消、恢复 | 每轮最多 256 次模型调用/3 轮修复，默认 48 次调用/2 轮；真实 API 和游戏效果未验 |
| 完整作品版本 | 当前项目状态、素材/工程/成功产物关联、恢复前自动存档、旧产物下载、完整备份迁移 | 最多 100 版；恢复清除执行批准；手工模式需显式保存 |
| 网页模型设置 | 最多 20 个文本/图像配置、即时启用切换、密钥保留/删除、环境变量回退 | 服务端私有文件，接口不回传密钥；保存不请求模型；请求运行时禁止修改 |
| 自带 AI | Chat Completions、独立 Images generations/edits、选定 PNG 视觉输入 | 真实服务按要求跳过；非流式；不保证各供应商所有协议兼容 |
| 需求创作 | 2–4 个方案、最近 100 次记录、12 次上下文、当前规格与修改指令、token 用量 | 固定演示明确标记；不保存模型私有思维过程 |
| 内容 | 普通物品、食物、工具、闪电法杖、方块、两类实体 | 能力由目标注册表决定，见下表 |
| 自定义掉落 | 五目标支持方块/实体掉落，每对象最多 8 条、数量范围、独立概率、实体玩家击杀条件 | 无时运/抢夺/精准采集；Java 方块带爆炸存活条件，Bedrock 由其游戏行为处理；未游戏实测 |
| 配方 | 有序/无序、九宫格、按版本原版 ID 搜索与验证 | 原版注册表是随仓库分发的固定数据，不在线爬取 |
| 像素/图片 | 16/32/64 编辑、橡皮/填充/撤销、PNG、图像 API、本地缩放/调色板量化 | 图像 16–2048 像素、最大 6 MiB；不自动下载模型返回的 URL |
| 方块模型 | 五目标静态立方体模型绑定，内置贴图/显式覆盖，自动创作，透明面与资源引用检查 | 碰撞与选区仍是完整方块；Bedrock 不支持 Java rescale/UV 面旋转；客户端视觉未验 |
| 独立工坊 | 不建模组项目即可绘制/导入/生成/继续修改模型与贴图，素材跨项目复用 | 自带 API 质量未实测，离线编辑和导出独立可用 |
| 静态模型 | 128 个立方体、内置贴图与完整 bbmodel、UV、隐藏面/UV 旋转、Java 单轴旋转/rescale、显示变换 | 不支持任意网格；模型编辑不是完整 Blockbench |
| 动画 | 可选 128 个层级骨骼/32 层、多立方体归组、多轴绑定、8 片段/512 总关键帧、线性旋转/平移/缩放、实时播放 | 无蒙皮/任意网格/曲线/表达式；游戏集成仅 Bedrock，保守空间范围有导出上限 |
| 预览 | 本地 Three.js、贴图、点选、相机、人形参考、手持/头戴/物品栏/掉落、PNG 截图 | 人形参考和 WebGL 不代表 Minecraft 渲染实测 |
| 文件互通 | 静态 bbmodel、层级骨骼/多立方体/线性动画 bbmodel、Bedrock geometry/animation | Java 静态格式不接收骨骼；不执行表达式；不支持的输入明确报错 |
| 资源共享 | 不可变素材、哈希/来源/许可、库搜索、资源包、原创 CC0 目录和 PR 贡献流程 | 本地开放目录，不是托管市场或在线账户系统 |
| 项目管理 | 搜索/重命名/归档/复制、规格导入导出、20 版历史、完整项目备份迁移 | 单进程本地文件存储；备份限 32 MiB |
| 工程 | 固定适配器、快照/差异/源码审查、批准、完整源文件和 wrapper | 仅接受受控命名空间的 Java/JSON 修改；导入的工程需重新生成才可执行 |
| 服务端验收 | 四 Java 目标 GameTest、注册/配方/实体属性/方块掉落、断网运行、原始报告、版本与备份关联 | 按实际规格生成用例；不覆盖任意 AI 玩法、客户端渲染或多人兼容 |
| 构建 | 固定摘要容器、真实日志、取消/超时/重启中断、旧产物保留 | Java 每次最多 1 个构建，默认 4 GiB/2 CPU/10 分钟；Bedrock 无 Docker |
| 交付 | 经哈希与结构校验的 JAR/MCADDON，源码+报告+安装说明 ZIP | 编译与打包都不等于游戏实测 |
| 本地发行 | 源码、生产依赖、启动脚本、文件清单/SHA-256、解压启动验证 | Node24.5+ 另装；无签名桌面二进制，Java 构建需另装 Docker |

## 目标能力

| 内容 | Fabric 1.20.1 / 1.21.1 | Forge 1.20.1 / NeoForge 1.21.1 | Bedrock 1.21.60 |
| --- | --- | --- | --- |
| 普通物品、食物、实心方块、配方、贴图 | 支持 | 支持 | 支持 |
| 剑/镐/斧/锹/锄、闪电法杖 | 支持 | 支持 | 未支持 |
| 自定义静态方块模型 | 支持 | 支持 | 支持 |
| 自定义静态物品模型 | 支持 | 支持 | 未支持 |
| 僵尸/牛实体、数值、贴图、刷怪蛋 | 原版原型及行为 | 原版原型及行为 | 简单敌对/被动 AI，非完整原版行为 |
| 自定义实体模型、动画 | 未支持 | 未支持 | 支持受限立方体动画 |
| 方块与实体自定义掉落 | 支持 | 支持 | 支持 |
| 自然生成、自定义繁殖流程 | 未支持 | 未支持 | 未支持 |
| 验证 | 两目标真实编译 | 两目标真实编译 | 包结构/资源引用 + 浏览器链路 |
| 游戏实测 | 两目标临时服务端检查 | 两目标临时服务端检查 | 未进行 |

Java 实体贴图要求 64×64，匹配原版模型归一化 UV；牛的 64×32 原始布局需纵向放大两倍。Bedrock 允许 16/32/64 贴图，实体绑定模型不接受 Java rescale/UV 面旋转。

资源库上限 500 项，每个项目最多 100 个工程快照；没有自动磁盘清理器。这些本地 JSON 限制不等于 Hub 的共享元数据事务；Hub 提供认证、跨设备同源工作台、积分和在线市场，部署边界见 HOSTED.md。盔甲/维度/自定义 GUI/任意行为代码与其他游戏版本未实现，不将未来计划当成交付功能。
