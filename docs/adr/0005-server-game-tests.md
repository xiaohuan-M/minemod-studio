# ADR 0005：编译产物与服务端运行证据分离

Gradle 构建成功只能证明可编译。游戏验收是另一种异步任务，绑定本轮不可变工程、已批准哈希和成功构建；不能把服务端检查任务当成 JAR 产物。自动创作与手工构建都可调用同一个检查器。

生成器为四个明确 Java 目标生成固定检查代码与计划，放在 AI 不允许修改的测试命名空间。计划包含目标、用例、检查源哈希和 `headless-server` 范围。注册、配方加载、实体属性和方块放置/掉落范围根据已验证规格生成，不是任意玩法的完整测试。测试通过后由检查器写出逐项 JSONL；仅进程退出 0、日志出现成功文本或报告缺项均不能通过。

运行分两阶段。第一阶段按用户网络授权解析固定 Gradle/加载器运行依赖，不启动 Minecraft。Forge 的运行任务可能作为准备任务终结器，需要显式跳过；Forge 的客户端资源任务、NeoForge ModDev 2.0.148 的客户端资产属性依赖也单独处理，避免为无界面服务器下载数千音效和贴图。NeoForge 仅为服务端 PrepareRun 提供标明 headless 的资产属性，不替换服务端库、游戏数据或真正测试任务。

第二阶段是独立 `--network none` 容器，Gradle 离线运行真正 GameTest 服务器；无外部玩家、无客户端视觉判断。延续固定镜像、只读根、独占工作目录、去能力、4 GiB/2 CPU/10 分钟限制；限制 JVM 处理器和堆，避免多个 JVM 按宿主资源估算导致 OOM。准备失败属于环境错误，不交给模型改代码；实际游戏检查失败才进入有界代码修复。

报告哈希独立关联完整作品版本，备份包含报告字节。迁移只能保存“来自外部的验证证明”，不可将导入记录升级为本机已验，也不能执行外部源码。客户端、视觉、复杂玩法和多人兼容始终是独立证据，不能由 `gameTested` 的服务端结果推断。
