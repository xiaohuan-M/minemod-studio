# 产品需求 · v0.1

日期：2026-10-22。状态：开发基线，可随真实验证修订。

## 1. 产品定位

让不熟悉 Java 的 Minecraft 创作者在自己的电脑上，用自然语言逐步完成一个可理解、可修改、可回滚的模组。核心价值是把创作过程和工程掌握在自己手中，提供自带模型 API、本地模型与可导出源代码的选择。

首要用户：有明确玩法想法的 Minecraft 玩家、学习模组开发的初学者，以及希望快速验证玩法的技术创作者。第一版以桌面电脑上的本地浏览器为入口；手机仅预留响应式布局，不承诺远程访问与跨设备同步。

## 2. 首个完整体验

验收用例：用户要求“增加月光锤物品和合成配方”，选择预定义的 Fabric 目标，看到规格和制作计划，确认后生成工程、查看差异，再批准隔离构建。得到构建报告、源码与可下载的 JAR，最后在独立测试游戏实例中检查物品名称、贴图和配方。

先实现普通物品与配方。复杂右键行为、生物 AI、网络同步和自定义渲染不作为第一个闭环的依赖。

## 4. 关键交互

工作台优先展示“当前作品、制作计划、改动内容、下一步”。对话用于表达与修订需求，不把所有操作塞进聊天记录。创作者应始终知道现在处于规划、生成、等待授权、构建、失败还是完成。

- 模型设置：服务地址、模型、能力探测、连接测试；密钥只存服务端，界面仅显示是否配置。
- 工程变更：创建快照，展示改动文件与风险说明，用户可拒绝本次变更。
- 构建前：展示模板来源、命令参数、联网需求和隔离能力；不满足环境要求则阻止启动。
- 构建后：区分“构建成功”“运行验证成功”“用户游戏实测成功”。失败显示原因和可重试步骤。
- 进度：步骤状态来自实际事件；mock 必须永久带演示标签。

## 5. MVP 验收

1. 无开发经验用户可按 README 启动本地应用并创建项目。
2. 一个经过预先验证的 provider 可输出受约束规格；无效响应最多修复两次，仍失败则保留需求并停止。
3. 相同模板与锁定依赖能重复生成工程；未确认的模型输出不会执行。
4. 首个物品与配方工程通过真实 Gradle 构建；构建日志可追溯到工程快照。
5. 错误修复有轮数、费用与超时上限，可随时取消；失败不损坏上次成功版本。
6. 导出包含来源、目标版本和 SHA-256；没有成功构建证据时禁止把文件标注为“可用 JAR”。
7. 在 Windows / macOS / Linux 完成应用冒烟测试；实际模组构建逐平台记录结果。
8. 游戏运行测试需单独记录，不能由编译状态推断。

## 6. 暂不做

多版本与多 Loader、基岩版、云账号、积分充值、多人协作、模型市场、自动运营、自动操控游戏、完整 Blockbench 自动化、自动下载或覆盖用户存档。待基础闭环经过验证后再逐项评估。

## 7. 效果指标

记录本机可查看的任务时长、模型请求次数、已知费用或 token 用量、构建次数、导出结果；不默认上传遥测。首轮实验关注新用户完成首个有效工程的比例和失败原因，而不是对话条数。具体性能与成功率目标在首批真实样例后设定，当前不作无依据承诺。
